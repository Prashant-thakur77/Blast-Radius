The problem

The diff shows nineteen tidy files. It can’t show the caller it missed.

  • Reviewers read diffs. Damage lives in callers, other subsystems and team rules.
  • Same-typed arguments swapped: TypeScript passes, CI is green.
  • The bug ships and the team pays for it in rework.

The solution

BlastRadius maps what a PR can break, and IBM Bob reviews with the map.

Engine

Code graph in under a second

tree-sitter over git refs. Dependents, subsystems, signature changes, missed callers, untested units, ADRs in scope. A 0–100 score with a reason for every point.

IBM Bob

The reviewer

MCP server, BlastRadius Reviewer mode and skill. Stops for a human, reads ADRs, sends a subagent into each subsystem, proposes fixes.

Proof

Tests that ran

Subagents write vitest regression tests against a real in-memory database. A red test is a finding. Granite on watsonx.ai writes the summary.

Business value

Less rework, fewer bugs that pass CI.

  • Reviewers start from what the change can break. Every finding carries a file and line, so there is nothing to argue about.
  • The evidence is deterministic and takes under a second. The model only explains it, so a flaky model can't turn a risky PR green.
  • One engine, three places: Bob IDE for reviewers, the CLI for developers, CI with a merge gate and Bob Shell.
  • Next: more languages, and a history of past reviews Bob can query through MCP.
